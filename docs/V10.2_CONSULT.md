# V10.2 技术方案与会诊咨询（GLM-5.3-Flash MTP draft 微调，serving 接受率修复）

> 会诊文档 v1（2026-11-23）。目标读者：MTP/投机解码微调方向的专家。
> 北极星指标：vLLM serving 的原生前缀接受长度 K̄（382 用例三组，
> /metrics 计数器）。所有"有效性"结论以 K̄ 为准。

## 一、目标与栈

- **目标**：GLM-5.3-Flash（MoE，45 层，KDA/DSA 混合注意力，288 专家）的
  MTP draft 微调，使 vLLM 投机解码（deepseek_mtp, K=5）的接受长度显著
  超过 base（纯 vendor 权重）的 **K̄=3.52**。
- **栈**：LF 数据管线 + mcore 0.18.2（TP16，16×910B），vendor BF16 全精度。
  serving = vllm-ascend 0.30（BF16，无量化）。
- **训练范围**：主模型 LoRA（r=16，attention/MLP 线性层，词表两层冻结）
  + MTP 子树全参。8 卡机数据/seed 与对照 run 严格一致。

## 二、实测数据（serving 真值）

| 臂 | 真实 K̄（含 bonus）| D1 条件接受 | 备注 |
|---|---|---|---|
| base（纯 vendor）| **3.521** | 0.843 | 唯一零工程介入臂 |
| cp500（V10 原版：纯 CE）| **2.487** | 0.702 | **−29%** |
| cp100（V10.1：CE 1.0 + KL 2.33 + agree 0.5 + margin 0.3）| 2.342（G1）/2.426（G2）/2.394（G3）| — | 三组全负 |
| **bisect**（LoRA-only，MTP 回滚 vendor）| **3.20+** | — | 恢复近 base |

**bisect 二分结论**：LoRA 合并无罪、导出流水线无罪（q_proj 数学对拍
6.98e-09）；**毒源 = MTP 子树的窄域微调本身**。

**拆分实验**（cp100 权重下，G2 的 98 条按"是否被 CP100 训过"拆分）：
训练过的 42 条 = 1.372 < 未训的 56 条 = 1.445（−0.073）——**训练过的样本
反而更差**，单次曝光无记忆效应，漂移均匀打击。

## 三、机理（与你们的框架对齐后的修正版）

1. 主干 N+1 训练、MTP 语料 N+2 训练（教科书目标 ✓ vendor 同款做到 3.52）
2. **差异不在目标，在分布覆盖面**：vendor MTP = 万亿 token 全域覆盖；
   我们的微调 = 30k 数学/QA（R1 think 链）窄域覆写 → 灾难性遗忘
3. 两层偏移：输入偏移（gold teacher forcing → 自生成上下文，exposure
   bias）+ 目标偏移（语料 N+2 → 主模型会选的 N+2）。窄域语料上两者
   近似重合（所以探针帧 +21 点）；分布外分叉（所以 serving 帧 −29%）
4. **token 级反向**：CE-on-gold 在"主模型 argmax ≠ gold"的位置上把 draft
   概率推离主模型的选择——serving 验收恰好按主模型 argmax 计。
   拆分实验"训过更差"是该反向的直接证据

## 四、已实施修复（对照你们的铁律 ①②⑤）

| （③ 量化校准）| N/A——BF16 serving |

## 五、咨询点（请专家裁决/纠偏）

1. **LR 分组配比**：MTP 2e-5 / LoRA 5e-6 是否合适？MTP 全参 6.7 亿参数
   （288 专家 × 单层）在该 LR 下的稳定性风险？需要 cosine decay 还是
   恒定？
2. **draft-CE 权重**：0.25 vs 0.1 vs 0——CE 完全归零的风险（draft 失去
   对语料的锚定后，agree-CE 是否足以防坍缩）？
3. **KL 形式**：目前 forward KL(p_main‖p_draft)。Reverse KL / TV 距离 /
   top-k 截断 KL——哪种对"argmax 接受率"更直接有效？
4. **exposure bias 的正解**：self-feed 已证伪（V5.2/V5.3 实测）。on-policy
   自生成数据的正确构建方式——用 base 主模型对 382 类业务 prompt 自生成
   response（含错误延续？还是只保留被验证的高质量延续？）训练集要多大？
5. **数据混合比**：业务数据（数学/QA）与通用回放数据的配比——防遗忘的
   经验比例？混合后 KL 锚定的训练分布覆盖是否足够？
6. **D1-only vs 多深度链训**：当前只训 D1 视界（N+2）。V8 配方的深度权重
   γ^(k-1)（D1-D5 链训，k≥3 只留 KL）——是否值得切换到多深度链训？
   多深度训练对 D1 接受率有无反噬（共享单层的多步梯度冲突）？
7. **预期量级**：全套配方正确后，K̄ 从 3.52 的现实增益上限估计？（主模型
   LoRA 业务拟合带来的分布锐化 + MTP 对齐修复的叠加效应）
8. **诊断缺口**：除 K̄/per-pos/D1-D5 矩阵/main-PPL 外，还应监控什么？

## 五b. 配置勘误与裁决（2026-11-23 专家审计后）

**勘误**：V10.2 实际运行配置 = draft-CE **0.0**（非文档 §四 的 0.25）+
**Top-128 截断 KL**（非全词表）+ margin 锚点 **va**（非 gold）+ **LR 分组**
（MTP 1e-5 / LoRA 5e-6）+ **cosine decay**。V10.2 相对 V10.1 为**多变量
联合改动**（5 项），单变量归因需后续消融臂——本 run 只作**配方级**对比。

**设计裁决（审计四）**：主模型 LoRA 联训保留（业务车道约束，单训 MTP 归
其它团队）；moving-target 以 LR 分组 + detach 缓解；bisect 的 3.20+ 记录
为"联训代价"基准，V10.2 判据相应调整为：K̄(V10.2) > K̄(bisect 3.20) =
MTP 对齐训练在联训约束下有正贡献；K̄ ≥ 3.52 = 追平 base。

**审计修复清单（全部落地）**：agree 覆盖 bug（_last_argmax_agree 存了
CE loss）✓、新签名测试重写（删假绿）✓、topk_kl 测试 ✓、
top-128 支撑外语义如实声明（agree-CE 兜底支撑外）✓、pad 掩码差异
挂账（对照 run 同样不掩，同基线成立）✓、**MTP 输入 dec.detach 落地
（师生分工：MTP 对齐 loss 不回传 LoRA）**✓。
