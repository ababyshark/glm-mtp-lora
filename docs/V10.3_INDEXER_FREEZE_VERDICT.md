# V10.3 Indexer 冻结裁决(最终视角 · 2026-11-25)

**问题**:B1 cp500/cp300 导出台账中 5 个 MTP 组件 delta=0(DSA indexer:wq_b /
wk / weights_proj / kpool_compress_gate / kpool_compress_ape)。它们到底该不该训?
对 MTP 提升有没有帮助?

## 1. 事实链(为什么零梯度)

1. **设计使然,非缺陷**:`v10_dsa.py:103-111` —— `@torch.no_grad()` 包裹整个
   indexer 前向(算分 → kpool 压缩 → top-k 选点),docstring 明示
   "indexer fully frozen (@no_grad forward)"。选点是**离散操作**,本移植版将其
   定性为纯路由:输出不可微 int32 索引,从不进入训练图。
2. **两 run 完全同模式**:Arm A cp100 与 B1 cp500/cp300 的 14 项 mtp 台账中,
   同样 5 项零 delta——系统性,与数据/配方无关。
3. **审计侧证**:R8 分桶审计(语义桶)里 **indexer 桶从未出现过**——零梯度参数
   被 `g is None` 过滤,桶根本不生成。侧证训练图确实不回传。
4. 参数虽在 CP(可训练集、requires_grad=True),但 `@no_grad` 前向使其实际
   永不更新 → 导出忠实反映 CP → serving indexer 恒为 factory 权重。

## 2. 判决:不解冻(最终视角)

| # | 论据 | 展开 |
|---|---|---|
| 1 | **router-collapse 前科** | V10.3 冻结面的由来就是窄域训练打碎脆弱路由结构(MoE router 崩)。indexer 是同类结构且**更脆**:router 错 = 软混合劣化,indexer 错 = 整个注意力拓扑选错(离散、不可挽) |
| 2 | **train/serve 一致性红利** | 训练用 factory 路由、serving 也用 factory 路由——draft 在"它 serve 时的路由规则"下训练,零偏移。解冻训练反而制造新的训推不一致,且 vLLM-ascend 的 indexer 推理 kernel 对新权重分布未经验证 |
| 3 | **杠杆错位** | 接受率瓶颈在预测头与数据对齐:indexer 冻结着,B1 的 EVAL-FIXED agree 照样 0.67→0.84 平台。factory 路由正是 **base K̄ 2.60 的组成**——冻结保住了底座 |
| 4 | **重造成本高** | 训 indexer 需重造可微目标(DeepSeek 原版:score-加权软注意力辅助路径)+ serving-parity 验证 + 处理 fp8/kernel 边界——投入产出比在所有候选项中垫底 |

## 3. 提升杠杆排序(最终视角)

```
1. 数据侧 on-policy(B1 验证中)                ← 已验证方向,判决今晚
2. T7b 冻结主模型纯草稿蒸馏                     ← TODO 在册
3. 多深度训练(D2-D5;当前只有深度 1 在学)      ← V10.1 d15 矩阵支撑
4. cutoff 2048(长链后半段进入训练视野)        ← 在册,随 B1+ 落地
5. 训 indexer                                  ← 不推荐:高风险重造,排序垫底
```

## 4. 附带产出:审计盲点登记

R8 语义分桶审计对"**可训练但零梯度**"的参数不可见(被 `g is None` 过滤,
桶不生成)。本轮 indexer 即属此类——桶列表"全 >0"并不代表可训练集全部有梯度。
**后续版本**:审计应显式列出 `requires_grad=True 且 grad is None` 的参数清单,
防止"训练图静默旁路某子模块"这类情况再次不可见。

## 5. 若未来重议(前置条件)

只有同时满足才值得重开:① 有可微 indexer 训练目标(软注意力辅助路径)实现;
② serving kernel 对任意新权重分布的 parity 验证通过;③ 多深度训练与 T7b 落地
后接受率仍卡在路由瓶颈(需先用探针证明瓶颈在选点而非预测)。
